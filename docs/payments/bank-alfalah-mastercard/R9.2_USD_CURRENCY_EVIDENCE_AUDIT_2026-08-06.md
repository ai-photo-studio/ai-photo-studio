## 2. The one contradiction, in full

`P4D_MPGS_FINAL_LOCAL_INVESTIGATION_2026-08-05.md` independently compared the
**retired** Alfa APG integration guide against the **current** MPGS V100
adapter, field by field. One row reads:

| Field | Retired Alfa APG (legacy, different protocol) | Current MPGS adapter (this repository) |
|---|---|---|
| PKR/USD capability | PKR only ("Currency ... will always be PKR") | PKR enabled (`standard-pattern-fallback`); USD gated separately, bank-confirmed for sandbox testing only |

This is the sole place anywhere in this repository's evidence where a
PKR-only claim appears. It describes a **different, already-retired**
protocol (Alfa APG — see `p4c-bank-alfalah-legacy-apg-retired.test.ts`, which
permanently guards against that protocol's reintroduction) and is recorded,
not reconciled, per this repository's standing practice of never silently
resolving a documented contradiction. It is **not** evidence that the
current MPGS integration — the one this packet tests — is PKR-only.

No document anywhere in this evidence set claims MPGS is **USD-only**
either. This audit did not infer USD-only status merely because some
generic MPGS/Mastercard documentation elsewhere in the industry commonly
uses USD as its example currency in code samples — no such inference was
drawn or relied upon anywhere in this repository's code or evidence; USD
enablement here rests exclusively on the bank's own direct, merchant-profile
-specific confirmation (§1 above), never on a generic third-party example.

## 3. Conclusion driving this packet's USD dry-run and live diagnostic

- `MPGS_CURRENCY_SUPPORT.USD.enabled = true` (evidence tier
  `doc-confirmed-live-fetch`, the strongest tier used in this codebase) is
  already correct and required no code change.
- The one open blocker (`P4C_MPGS_AUTH_VERIFIED` not achieved, `HTTP 401` on
  the PKR leg) is profile/credential-level per the evidence above, not
  currency-level — so a USD attempt is expected, per this packet's own
  classification rule (§5 of the task), to either bypass it (if the
  blocker were somehow currency-specific, which no evidence supports) or
  reproduce the same `401` (confirming it is currency-independent, as the
  evidence in this document already strongly suggests).
- Neither PKR nor USD is `SANDBOX_VERIFIED` as of this document.

## 4. Permanent protection

See `rules.md` for a new permanent rule: example currency values in generic
third-party MPGS/Mastercard documentation must never be treated as
merchant-profile currency authority. Only a bank-specific, merchant-profile
-specific confirmation (an email, a portal statement, or a successful
bounded sandbox test) may enable or disable a currency in
`MPGS_CURRENCY_SUPPORT`.
